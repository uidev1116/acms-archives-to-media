# ArchivesToMedia

a-blog cms の `archives/` 配下の画像・ファイルを参照しているユニット・カスタムフィールドを、メディア参照へ一括変換するプラグイン（拡張アプリ）です。

## 概要

画像ユニット・ファイルユニット・画像フィールド・ファイルフィールドを、a-blog cms のメディア機能（メディアユニット・メディアフィールド）へまとめて移行します。変換前に何が変わるかを確認でき（ドライラン）、変換後は元に戻せます（ロールバック）。共用レンタルサーバーのタイムアウトに耐えるよう、チャンク単位で実行・再開できます。

フィールドの書き込み先は、既定では**同名**です（メンテナンス画面にした状態や、テスト環境で実行して切り替える運用を想定しています）。テンプレートを段階的に移行したい場合は、別名（`{fd}_media`）に書き込み、旧データを残すこともできます。

## 主要機能

- **ドライラン**: 変換前にスキャンして、件数・種類別の内訳・元ファイルが無い行・新規登録／再利用の見込みを確認できます（何も書き換えません）
- **ユニットの変換**: 画像ユニット（`image` / `image_*`）・ファイルユニット（`file` / `file_*`）をメディアユニットへ変換します（多言語ユニットにも対応）
- **フィールドの変換**: 画像フィールド・ファイルフィールドをメディアフィールドへ変換します。エントリーのほか、カテゴリー・ブログ・ユーザー・モジュール・カスタムユニットのカスタムフィールドにも対応しています（所属は設定画面で選べます）
- **書き込み先の選択**: 同名（既定）／別名（`{fd}_media`）／フィールドごとの名前指定
- **フィールドグループ対応**: フィールドグループ（カスタムユニット内も含む）の定義に、書き込み先のフィールド名を自動で追記します
- **リビジョン対応**: 設定でオンにすると、リビジョン（`column_rev` / `field_rev`）も変換します
- **メディアの重複排除**: 内容が同じファイルは、既存のメディアを再利用します（SHA-256）。large 版があれば優先して登録します
- **ロールバック**: 変換前の状態へ完全に戻せます。変換後に編集された行は戻さず、エラーとして残します
- **変換の確定**: 結果を確認し終えたら、ロールバック用の記録（スナップショット）を削除して DB の容量を回収できます（確定後はロールバックできません）
- **旧データのクリーンアップ**: テンプレート移行後に、旧キー（`{fd}@path` など）を削除できます（ロールバックで戻せます）
- **チャンク実行**: 一時停止・再開ができます。タブを閉じても、過去の実行から続きを再開できます
- **編集ロックの尊重**: 編集ロック中のエントリーはスキップします。また、エントリーの保存・リビジョン切り替えと同じ排他ロック（コアの `UnitLock`）の中で書き込むので、保存と重なって変換が上書きされることを避けます
- **CSV 出力**: 結果を CSV でダウンロードできます
- **テンプレート移行のヒント**: 旧変数 → 新変数の書き換え例と、メディアフィールドの入力欄をコピーできます

## インストール方法

プラグイン（拡張アプリ）をダウンロード後、zip ファイルを解凍して `extension/plugins/` に設置します。

設置が完了すると、「管理画面 > 拡張アプリ」に `ArchivesToMedia` という名前で表示されるので、インストールをクリックしインストールします。拡張アプリは**ブログごとに有効化**します。

プラグインを更新したときは、同じ画面で「アップデート」を実行してください（テーブル定義を最新にします）。

## 使用方法

管理画面の「アーカイブ → メディア変換」を開きます。

### 1. 設定

- 変換する対象（画像ユニット / ファイルユニット / 画像フィールド / ファイルフィールド）を選びます
- ユニット種類のマッピング（変換元 → メディアユニット）を確認します
- フィールドの書き込み先（同名 / 別名 / カスタム）と、対象にする・除外するフィールド名を指定します
- リビジョン・子ブログ・対象エントリーの状態・フィールドの所属などを選びます

### 2. スキャンと確認

「スキャンして確認へ」で、何も書き換えずに候補を一覧します。

- 種類別の件数、元ファイルが見つからない行（`SOURCE_NOT_FOUND`）などを確認できます
- 変換したくない行は除外できます（絞り込んで一括除外もできます）

### 3. 実行

「変換の実行へ」→ DB バックアップ済みにチェック →「変換を開始する」で実行します。

- 進捗・件数・ログがリアルタイムに表示されます
- 「一時停止」で、実行中のチャンクが終わったところで止まります。「再開」で続きから進みます

### 4. 結果

- 変換済み・スキップ・エラーの件数を確認できます
- 「結果を CSV でダウンロード」「スキップ・エラー分を再実行」ができます
- 「旧データを削除（クリーンアップ）」で、旧キーを削除できます
- 「ロールバック」で元に戻せます。「このジョブで新規作成したメディアのうち、参照が無いものを削除する」は任意です（既定はオフ）。変換後に編集されていて戻せなかった行は、エラーとして残ります
- 「変換を確定する」で、ロールバック用の記録を削除します（容量の回収。確定後はロールバックできません。結果の件数と CSV は残ります）。別名モードで旧データのクリーンアップが済んでいない場合は、確定するとクリーンアップできなくなるため、確認が必要です（先にクリーンアップするのがおすすめです）
- ロールバック中に、エントリーが別の処理（保存など）で更新中だったアイテムは、戻さずに残し、ジョブを「ロールバック中」のままにして、画面にメッセージを出します。しばらくしてから、もう一度「ロールバック」を実行してください（編集ロックが放置されて長く残るときは、そのエントリーのロックを解除してから）

過去の実行は、「過去の実行」からジョブ詳細（概要・アイテム一覧・ログ）を開けます。

## 変換の挙動

- 変換先は現在のブログです（「子ブログも含める」をオンにすると、配下のブログも対象になります。各ブログの管理権限が必要です）
- 画像ユニット・ファイルユニットは、ユニットの種類をメディアユニットに書き換えます。レイアウト（サイズなど）は変わりません
- 同名モード（既定）では、同じ所属の `{fd}` と `{fd}@*` の行を、メディアの値で置き換えます（旧キーは削除。ロールバックで復元できます）
- 別名モードでは、`{fd}_media` と `{fd}_media@media` を追加します。旧データは変わりません
- 新規メディアのタグには `archives-import`、alt・キャプションが設定されます
- 内容が同じファイルは既存のメディアを再利用します。コアの重複検出は実行ブログから選べる範囲で探すため、別のブログのメディアを再利用することがあります（その場合、アイテムに警告 `MEDIA_OTHER_BLOG` が付きます）
- 元ファイルが無い・サイズ上限を超える・許可されない形式などの行は、データを変えずにスキップします
- archives の元ファイルは削除しません

### 対象外

- テンプレートの書き換え
- 本文 HTML 内の `<img src="/archives/...">`
- 外部ストレージ上のファイル

## 再実行時の注意

- 変換済みのアイテムは、再スキャンしても対象になりません（何度実行しても同じ結果になります）
- スキップ・エラーになった分は、原因を直したあとに「スキップ・エラー分を再実行」できます
- 同じブログで、同時に別の処理を実行することはできません（ロックされます）
- メディアの登録中に別の処理が登録中だったとき、エントリーが保存などで更新中だったときは、`MEDIA_REGISTER_FAILED` / `ENTRY_LOCKED` でスキップします。少し待って「スキップ・エラー分を再実行」してください
- テンプレートを直す前に管理画面でエントリーを再保存すると、書き込んだ `{fd}_media` は消えます（旧キーは残るので表示は壊れません）。テンプレート更新後にもう一度実行すると揃います

## Tips

### テンプレートを新しい書き方に移行する

別名モードで変換したあとは、結果画面の「テンプレート移行のヒント」に、フィールドごとの書き換え例が出ます。

```html
<!-- 旧 -->
<img src="%{ARCHIVES_DIR}{hero@path}" alt="{hero@alt}">

<!-- 新 -->
<img src="{hero_media@path}" alt="{hero_media@alt}">
```

入力欄は、メディアフィールドの書き方（`js-media-field`）に置き換えます。ヒントの「コピー」ボタンで、表示側と入力欄をまとめてコピーできます。ヒントは固定の書き換え例を表示するだけで、テンプレートの中身は読んでいません。

テンプレートの移行が終わったら、「旧データを削除（クリーンアップ）」で旧キーを消せます。新しいフィールド（メディア）が無い行は、データを失わないよう削除しません。

### アンインストール

ロールバックできる変換済みアイテムが残っていると、アンインストールは中止されます（ロールバック情報ごとテーブルを削除してしまうため）。管理画面には単に「失敗」と表示されるので、理由は監査ログで確認してください。先にロールバックするか、変換を確定するか、不要であれば `config.user.php`（`ablogcms/` 直下） に次を追加してから実行してください。

```php
define('ARCHIVES_TO_MEDIA_FORCE_UNINSTALL', true);
```

## トラブルシューティング

### よくある問題

**Q: 画面が表示されない**
- 拡張アプリがそのブログで有効化されているか確認してください
- 管理画面の URL は `admin/app_archives_to_media_index/`（`app_` 付き）です

**Q: 画面や操作で 500 エラーになる**
- プラグインを更新したあと、「アップデート」を実行していない可能性があります（新しい列が無い状態です）
- 詳細は管理画面の「監査ログ」で確認できます

**Q: `ENTRY_LOCKED` でスキップされる**
- そのエントリーが編集ロック中です。ロックが外れてから「スキップ・エラー分を再実行」してください
- 編集ロック機能が使えないサイトでは、実行中にエントリーを保存しないでください

**Q: `SOURCE_NOT_FOUND` / `SOURCE_FORBIDDEN` / `SOURCE_TOO_LARGE` / `SOURCE_INVALID_MIME` でスキップされる**
- 元ファイルが無い、archives の外を指している、サイズ上限を超えている、許可されない形式のいずれかです。ファイルやパスを直してから再実行してください

**Q: 大量データでの処理が遅い**
- 1 回に処理する件数（チャンク）は、既定 20 件＋時間の上限です。進捗は DB に残るので、途中で止まっても再開できます
- 数十万件規模では、ロールバック用のスナップショットでテーブルが大きくなります。結果を確認し終えたら「変換を確定する」で回収できます

## 開発者向け情報

このプラグインは [appleple/acms-plugin-skeleton](https://github.com/appleple/acms-plugin-skeleton) をもとにしています。`src/` が `extension/plugins/ArchivesToMedia/` にリンクされるプラグイン本体です。

```bash
# PHP（a-blog cms 本体を含む環境の中で。テスト用 DB は環境変数で渡す）
composer install
vendor/bin/acms-create-database    # 初回のみ
composer check                     # phpcs + PHPStan (level max) + PHPUnit (Unit / Integration)

# フロントエンド（frontend/ → src/assets/dist/）
npm ci
npm run build                      # src/assets/dist/archives-to-media.js（コミットしない。CI / リリースでビルド）
npm run lint                       # ESLint + Prettier + Stylelint
npm run typecheck
npm run test:coverage              # Vitest（カバレッジ 90% 以上）
```

PHP のカバレッジは pcov または Xdebug で `vendor/bin/phpunit --coverage-text` を実行します。

### フロントエンドの開発環境

- Node.js 22.12 以上。Volta を使う場合は `package.json` の `volta`（22.19.0）で自動的に切り替わります。nvm / fnm などは `.nvmrc`（22）を読みます。`npm ci` で依存と Git フックが入ります（husky）。
- **コミット時**（`pre-commit`）: 変更したファイルに lint-staged で ESLint（`--fix`）・Prettier・Stylelint を自動実行します。
- **push 時**（`pre-push`）: 型チェックと vitest を実行します。
- `npm run lint`（チェックのみ）／`npm run lint:fix`（自動修正）／`npm run check`（lint + 型チェック + テスト）。
- ESLint は typescript-eslint・react-hooks・jsx-a11y（アクセシビリティ）を有効にし、整形のルールは Prettier に任せています（eslint-config-prettier）。`.editorconfig` でエディターの設定をそろえます。
- フックを一時的に飛ばすときは `HUSKY=0 git commit ...`。CI（`npm run lint` など）では必ずチェックされます。

### E2E（Playwright、ローカル専用）

実際の管理画面で「設定 → スキャン → 実行（一時停止・再開）→ 結果 → ロールバック → CSV」を通しで確認します。ローカルの a-blog cms と Docker の DB が必要なため、CI では実行しません。

```bash
npx playwright install chromium    # 初回のみ
npm run e2e
```

`.env.local`（コミットしない）に管理者の `A2M_ADMIN_MAIL` / `A2M_ADMIN_PASS` を書いておきます（`e2e/env.example` を参照）。そのユーザーは、子ブログにログインできる設定（ユーザーの「どのブログからでもログイン」）が必要です。実行前に `e2e/seed-a2m-test.php` で子ブログ `a2m-test` のデータを未変換の状態に作り直します（親ブログには触れません）。コンテナ名や URL を変える場合は `A2M_WEB_CONTAINER` / `A2M_DB_CONTAINER` / `A2M_DB_NAME` / `A2M_BASE_URL` を指定します。
